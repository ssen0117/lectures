오늘 끝에는 CS메모로 돌아가는 작은 업무 앱 하나가 손에 떨어집니다. 설명서 한 장 쓰면, 나머지 둘은 복붙 2번이면 끝.

FLOW

  1. 작업 설명서 쓰기 (10분)
  2. 앱 선택 + 바이브코딩 (20분)

사전 세팅 모듈 3과 같은 Claude 프로젝트에서 새 세션을 열고, 세션 시작하면 폴더 접근 권한을 다시 한 번 허용. CS메모는 Knowledge에 그대로 살아있어서 재업로드는 안 해도 돼요.
STEP 1 작업 설명서 쓰기

작업 설명서
쓰기

"앱 만들어줘" 했는데 엉뚱한 거 나온 경험, 한 번쯤 있죠? Claude 탓이 아니라 설명이 부족해서예요. 한 번 제대로 써두면, 그 다음부턴 복붙입니다.

STEP 1 · 복사 프로젝트 지식의 CS메모를 보고, 내가 [견적서 / 응대 스크립트 / 제안서 프롬프트] 생성기를 만들려고 해. 아래 3가지를 Claude가 바로 쓸 수 있게 한 장으로 정리해줘. 1. 뭘 만들까 2. 뭘 넣고 뭘 받을까 3. 어떤 데이터를 쓸까 다 되면 지금 폴더에 [앱이름]_설명서.md 로 저장해줘.
설명서 한 장으로 다음 앱도 답만 바꿔 쓰면 끝. 응대 스크립트 만들었으면, 같은 틀에서 '뭘 넣고 뭘 받을까'만 바꿔서 제안서용으로.
좀 더 깎아보기

고객 유형별 분기 규칙도 넣고 싶을 때

PROMPT · 분기 고객 유형별로 다르게 나오는 규칙도 한 줄 추가해줘. (모듈 3에서 쓴 유형 그대로)

나중에 봐도 바로 쓸 수 있게

PROMPT · 예시 각 항목에 예시 한 줄씩 넣어서, 나중에 다른 앱 만들 때도 바로 참고할 수 있게.

이 설명서, 개발자들은 PRD라고 불러요. 용어는 몰라도 됩니다 — 이 한 장이 있으면 Claude가 앱을 만듭니다.

STEP 2 앱 선택 + 바이브코딩

뭘 만들지
하나 고르기

세 앱 중 하나만 완주해도 OK. 같은 설명서 틀이니까 나머지 둘은 나중에 복붙.

STEP 2 · 복사 (선택한 카드로 바뀜) 폴더의 견적서 생성기_설명서.md 보고, 그대로 아티팩트로 만들어줘.
좀 더 깎아보기

고객 유형별 탭이 안 들어갔을 때

PROMPT · 유형 탭 상단에 고객 유형 선택 탭을 넣어줘. 유형 바꾸면 기본값도 자동으로 바뀌게.

CS메모의 실제 값을 쓰고 싶을 때

PROMPT · 실제 데이터 기본값·예시 데이터는 CS메모에서 유형별로 자주 나온 값으로 자동으로 채워줘.

결과를 바로 쓸 수 있게

PROMPT · 복사·다운로드 결과 화면에 "복사" 버튼과 "다운로드" 버튼 추가해줘.

PROMPT · 저장 생성한 결과를 지금 폴더에 저장하는 기능도 넣어줘. 파일명은 날짜_고객명.md 로.
여기까지 왔다면 설명서 한 장으로 앱 하나 만들어봤죠? 같은 설명서에서 '뭘 만들까' '뭘 넣고 뭘 받을까'만 바꾸면 나머지 둘도 같은 방식으로 나와요. 복붙 2번이면 끝.

올리기 전에
한 가지만

어느 서비스를 쓰든 공통이에요. 파일 이름을 index.html로 바꿔두세요.

파일명을 index.html로

배포 서비스는 도메인 루트에 접속하면 index.html을 찾습니다. 이름이 다르면 404 페이지가 떠요.

  1. Claude Artifact에서 다운로드한 HTML 파일을 찾아요
  2. 파일명을 index.html로 변경
  3. 이 파일을 서비스에 올리면 됩니다

여러 파일(이미지·css 등)이 같이 있다면 그 폴더 전체를 올리되, 첫 화면 역할 HTML이 index.html이어야 해요.

OPTION A Cloudflare로 올리기

Cloudflare에
올리기

Google 로그인 1분 + 파일 하나 올리면 공유 가능한 URL이 바로 나와요.

가입 (1분)

  1. dash.cloudflare.com/sign-up 접속
  2. 이메일 + 비밀번호로 가입 → 받은 메일에서 확인 링크 클릭

배포 — 4단계

  1. 좌측 메뉴 Compute → Workers & Pages → Create
  2. Upload your static files 선택
  3. index.html 파일을 창에 드래그드롭 → 프로젝트 이름 확인 후 배포
  4. 우측 상단 Visit ↗ 버튼으로 내 페이지가 뜨는지 확인
    URL 예: floral-butterfly-a6f3.내이름.workers.dev
수정본은 어떻게? 만든 Worker 화면 → 우측 상단 New deployment → 새 index.html 드래그드롭. URL은 그대로, 내용만 바뀝니다.
좀 더 깎아보기

404 "페이지를 찾을 수 없음"이 뜰 때

십중팔구 파일명이 index.html이 아니에요. 공통 준비 쪽 확인 후 재업로드.

이미지·CSS까지 같이 올리고 싶을 때

파일 여러 개를 한 번에 드래그하면 그대로 올라갑니다. index.html이 같은 경로에 있으면 돼요.

URL 이름을 바꾸고 싶을 때

Worker 화면 → Settings → 프로젝트 이름 변경. URL도 함께 바뀝니다 (기존 URL은 끊어져요).

OPTION B Netlify로 올리기

Netlify에
올리기

드래그드롭 한 번으로 URL이 나오는 가장 쉬운 서비스예요. 단, 네트워크에 따라 접속이 막히는 경우가 있어요.

가입 (1분)

  1. netlify.com → 우측 상단 Sign up
  2. 이메일 + 비밀번호 입력 → 받은 메일에서 확인 링크 클릭

GitHub 계정 있는 분은 "Sign up with GitHub" 선택하면 10초.

배포 — 3단계

  1. 로그인 후 상단 Add new site → Deploy manually
  2. index.html 파일을 창에 드래그드롭
  3. 자동 생성된 URL 확인
    URL 예: graceful-starfish-abc.netlify.app
수정본은 어떻게? 해당 사이트 → Deploys 탭 → 새 index.html 드래그드롭. URL은 그대로, 내용만 바뀝니다.
좀 더 깎아보기

URL 이름을 알아보기 쉽게 바꾸고 싶을 때

사이트 화면 → Site configuration → Change site name → 원하는 이름 입력.

급하게 한 번만 보여주고 싶을 때

Netlify Drop (app.netlify.com/drop) — 로그인 없이 드래그드롭, 24시간 뒤 사라짐.

이 URL이 강의장·회사망에서 안 열릴 때

Cloudflare(앞 쪽)로 같은 파일을 올리세요. 같은 결과, 다른 도메인.
