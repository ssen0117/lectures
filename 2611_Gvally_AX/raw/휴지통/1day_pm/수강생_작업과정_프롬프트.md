# 클라이언트 맞춤형 제안서 만들기 — 수강생 작업 과정과 프롬프트

> 터미널 없이, **폴더 정리 + 자연어 입력**만으로 진행합니다.
> 아래 프롬프트는 시뮬레이션(Spotify·토스·현대자동차 3사)에서 실제로 쓴 문장을 정리한 것입니다. `○○`는 클라이언트 이름으로 바꿔 입력하세요.
> 걸리는 시간은 시뮬레이션 기준 대략적인 값입니다.

---

## 한눈에 보기

| 단계 | 내가 하는 일 | Claude가 하는 일 | 결과물 |
|---|---|---|---|
| 0. 준비 | 폴더에 자료 넣기 | — | 마스터 PNG, 로고, 새 내용 |
| 1. 마스터 글로 만들기 | 프롬프트 입력 | PNG를 측정해서 디자인 가이드 작성 | `master/design.md` |
| 2. 클라이언트 색 정하기 | 프롬프트 입력 | 클라이언트 색을 쓸 자리와 색 코드 정리 | `clients/○○/design.md` |
| 3. PPT 만들기 | 프롬프트 입력 | 표지·장표·막대그래프 제작, 렌더링 검수 | `제안서_그래프추가_색조정.pptx` |
| 4. 점검·수정 | 결과를 보고 말로 수정 요청 | 색·내용 수정 후 다시 제작 | 수정된 PPT |
| 5. 마지막 확인 | PowerPoint에서 직접 열어보기 | — | 최종 제출본 |

핵심 아이디어: **"그림(PNG)을 글(design.md)로 바꿔 두면, 클라이언트가 바뀌어도 같은 규칙으로 일관되게 만들 수 있다."**

---

## 0. 준비 (직접 하는 일)

폴더를 이렇게 만들고 파일을 넣습니다.

```
master/slides/      ← 우리 회사 제안서 PNG (01_new.png, 02_new.png)
master/brand.json   ← 우리 회사 색
clients/○○/logo.png      ← 클라이언트 로고
clients/○○/brand.json    ← {"name":"○○","main":"#……","sub":"#……","logo":"logo.png"}
content/            ← 새 내용 (03_서비스구성.md, 04_교육커리큘럼.md, 05_도입효과.md)
```

- `main`은 클라이언트 대표 색, `sub`는 선택입니다. 공식 CI(브랜드 가이드) 페이지에서 HEX 값을 확인해 적으세요.
- 새 내용은 평문으로 써도 됩니다. 제목 / 헤드라인 / 항목 / 데이터 표 정도만 있으면 됩니다.
- 마스터 PNG는 **색을 최소한으로 쓴 디자인**이어야 합니다. 기본은 회색·검정, 색은 정해진 몇 곳(상단 바, 삼각형, 번호 원 등)에만 씁니다. 그래야 클라이언트 색이 들어왔을 때 충돌하지 않습니다.

## 1. 마스터를 글(design.md)로 만들기  (약 2~3분)

**왜 하나요?** 이미지는 눈대중으로 보면 간격과 크기가 매번 달라집니다. 코드로 측정한 수치를 글로 남기면 새 장표도 같은 디자인으로 만들 수 있습니다.

```
master/slides/의 PNG 두 장을 분석해서 master/design.md를 만들어줘.
우리 회사 제안서의 디자인 가이드를 글로 정리하는 거야.
색, 위치, 글씨 크기, 박스·화살표·번호 원·점선·헤드라인 박스 같은
반복 요소와 레이아웃 패턴을 포함해줘.
이미지를 눈대중으로 보지 말고 코드로 직접 측정해서
구체적인 수치(좌표·크기·색상 코드)로 적어줘.
문서 맨 앞에 디자인 원칙으로
"클라이언트 제안용 PPT는 클라이언트의 포인트 컬러와 맞추기 위해,
우리 자료의 색상을 최소한으로 쓰도록 디자인한다.
기본은 무채색이고, 색은 정해진 슬롯에만 쓴다."를 넣고,
이 마스터에서 색이 쓰이는 요소(슬롯) 목록도 정리해줘.
나중에 이 문서만 보고 새 장표를 같은 디자인으로 만들 수 있어야 해.
```

**확인할 것**
- 문서에 좌표·크기·색 코드가 숫자로 적혀 있는지 ("파란색 바" 같은 말뿐이면 다시 요청)
- 맨 앞에 디자인 원칙과 색이 쓰이는 자리(슬롯) 목록이 있는지

> 💡 **"코드로 직접 측정해서 수치로"** 문장이 품질을 좌우합니다. 빼지 마세요.

## 2. 클라이언트 design.md 만들기 (색조정안)  (약 1~2분)

**원칙:** 우리 색이 메인이고, 클라이언트 색은 **정해진 몇 곳에만** 씁니다.

| 클라이언트 색으로 바꾸는 곳 | 그대로 두는 곳 (우리 색 유지) |
|---|---|
| 제목 텍스트 | 헤드라인 박스(검정 테두리) |
| 강조 텍스트(박스 제목, 단계명, 핵심 수치) | 상단 바, 우하단 삼각형 |
| 그래프의 핵심 막대(도입 후) | 번호 원, 점선, 박스 테두리, 화살표 |

```
clients/○○/brand.json과 로고를 보고, master/design.md를
○○ 기준으로 수정한 clients/○○/design.md를 만들어줘.
우리 SAENA 컬러가 메인이고 클라이언트 색은 정해진 몇 곳에만 쓰는 "색조정안"이야.
○○ 색으로 바꿀 것:
(1) 제목 텍스트 색, (2) 그래프의 핵심 파트(도입 후 막대),
(3) 강조 텍스트(박스 제목, 단계명, 핵심 수치 같은 중간 제목·강조 글씨).
그대로 둘 것: 헤드라인 박스, 상단 바, 우하단 삼각형, 번호 원, 점선,
박스 테두리, 화살표는 모두 마스터 그대로(SAENA 색 유지).
글씨로 쓰는 ○○ 색은 흰 배경에서 잘 읽히게 필요하면 어둡게 조정해서 쓰고,
조정한 색 코드를 design.md에 적어줘.
각 색을 고른 기준도 적어줘. 로고는 표지에 넣어줘.
```

**확인할 것**
- 바꾸는 곳 / 그대로 두는 곳이 표로 정리되어 있는지
- 조정한 색 코드와 **고른 기준**이 적혀 있는지
- 서브 컬러(`sub`)를 임의로 쓰지 않았는지 (클라이언트가 지정하지 않았다면 메인 컬러만 사용)

> 💡 형광에 가까운 밝은 색(예: Spotify 초록)은 흰 배경에서 글씨로 읽히지 않습니다. "흰 배경에서 잘 읽히게"라고 쓰면 Claude가 어둡게 조정합니다.

## 3. PPT 만들기  (약 5~8분)

```
표지(클라이언트 로고, 'To. ○○' 포함, 표지도 무채색 중심 원칙을 따라)를 새로 만들고,
마스터 01, 02 장표를 이 디자인에 맞춰 넣은 뒤,
content/ 폴더의 03_서비스구성.md, 04_교육커리큘럼.md, 05_도입효과.md로 장표를 추가해줘.
03은 01의 2단 박스를 3단으로 늘리고 박스 사이에 화살표를 넣어줘.
04는 02의 가로 프로세스를 세로 방향으로 바꿔줘.
05는 템플릿 요소를 사용해서 막대그래프를 추가해줘(편집 가능한 차트, 04 뒤에).
기존 마스터 장표의 디자인 요소를 그대로 쓰고 ○○ design.md의 규칙을 적용해줘.
결과는 clients/○○/output/C_색조정/제안서_그래프추가_색조정.pptx 로 만들어줘.
편집 가능한 도형으로 만들 수 있는 건 도형으로, 새 장표는 반드시 도형·텍스트 상자로.
다 만든 뒤에는 이미지로 렌더링해서 마스터 PNG와 비교하고
어긋나거나 글이 넘치는 곳을 고쳐줘.
장표별로 흰색·회색·검정을 뺀 색 있는 픽셀 중 ○○ 색 비중(%)도 측정해줘.
빌드에 쓴 코드는 scripts/ 폴더에 저장해줘.
```

**결과:** 표지 + 마스터 01·02 + 새 장표 03(3단 박스) · 04(세로 프로세스) · 05(막대그래프) = 6장

**확인할 것**
- 새 장표가 이미지가 아니라 **도형·텍스트 상자**로 만들어졌는지 (PowerPoint에서 글씨를 클릭해 수정되는지)
- 막대그래프가 **편집 가능한 차트**인지 (차트 우클릭 → 데이터 편집)
- 글이 박스 밖으로 넘치지 않는지

## 4. 점검·수정 프롬프트 (결과를 보고 쓰는 말)

| 상황 | 프롬프트 |
|---|---|
| 색이 어색할 때 | `강조 색이 ○○ 느낌과 안 맞아. 조금 더 어울리는 다른 색으로 바꿔줘. 강조 글씨는 본문 글씨와 색으로 구분되게 해줘. 공식 팔레트에 있는 색을 우선으로 하고, 흰 배경에서 잘 읽히게 해줘. 제목과 나머지 요소는 그대로 둬.` |
| 핵심 숫자도 강조하고 싶을 때 | `평균 단축률 숫자(70%)도 강조 색을 적용해줘.` |
| 색의 근거가 궁금할 때 | `이 색을 고른 기준을 알려줘. 공식 CI에 있는 색인지도 확인해줘.` |
| 바꾼 이력을 남기고 싶을 때 | `어떤 색을 왜 골랐는지 clients/○○/design.md에 이전 색과 함께 "변경 이력"으로 남겨줘.` |
| 내용만 바뀌었을 때 | `content/의 03, 04 내용을 수정했어. 디자인은 그대로 두고 바뀐 내용으로 다시 만들어줘. 글이 길어지면 박스에 맞게 조정해줘.` |
| 새 데이터 장표를 추가할 때 | `content/05_○○.md의 데이터로 템플릿 요소를 사용해서 막대그래프를 추가해줘.` |
| 마음에 안 들어서 되돌릴 때 | `이전 색으로 되돌려줘.` (변경 이력에 이전 색이 남아 있어야 합니다) |

**꼭 기억할 한 줄**
> "더 어울리는 색으로"만 쓰면 Claude가 브랜드 팔레트 준수를 최우선으로 해석해서, 강조 글씨가 검정이 되는 등 **위계가 사라질 수 있습니다.**
> **"강조 글씨는 본문 글씨와 색으로 구분되게 해줘"** 를 꼭 같이 쓰세요.

## 5. 마지막 확인 (사람이 직접)

Claude의 검수는 "마스터와 비슷한지"까지입니다. 제출 전에 아래는 직접 확인하세요.

- [ ] **PowerPoint에서 열어보기** — 폰트, 줄바꿈, 차트 편집이 정상인지 (Claude는 LibreOffice로 확인하기 때문에 PowerPoint와 다를 수 있습니다)
- [ ] **표지 문구** — 제목·부제는 Claude가 지은 문구일 수 있습니다. 직접 고치세요.
- [ ] **예시 데이터** — 05 그래프는 예시 값입니다. 실제 수치로 교체하고 "※ 예시 데이터" 문구를 정리하세요.
- [ ] **로고 색** — 로고의 실제 색과 brand.json 색이 다를 수 있습니다 (예: Spotify 로고 `#1BD65D` vs `#1DB954`).
- [ ] **색 읽힘** — 강조 글씨와 막대가 흰 배경에서 잘 보이는지 눈으로 확인
- [ ] **클라이언트 브랜드 가이드** — 제3자의 로고·색 사용 제한이 있는지

## 자주 생기는 문제와 대처

| 문제 | 원인 | 대처 |
|---|---|---|
| design.md에 "파란색", "둥근 박스" 같은 말만 있다 | 측정 지시가 빠짐 | 1단계 프롬프트의 "코드로 직접 측정해서 수치로"를 넣어 다시 요청 |
| 클라이언트 색이 너무 많이 들어갔다 | 바꿀 곳을 지정하지 않음 | 2단계처럼 "바꿀 것 / 그대로 둘 것"을 명시 |
| 강조 글씨가 본문과 구분이 안 된다 | "어울리는 색"만 요청함 | "강조 글씨는 본문 글씨와 색으로 구분되게" 추가 |
| 글씨가 흐려서 안 읽힌다 | 클라이언트 원색을 글씨에 그대로 사용 | "흰 배경에서 잘 읽히게 어둡게 조정" 추가 |
| 글이 박스 밖으로 넘친다 | 내용이 길어짐 | "글이 길어지면 박스에 맞게 조정해줘" |
| 클라이언트의 서브 색이 엉뚱한 곳에 쓰였다 | Claude의 임의 판단 | "서브 컬러는 쓰지 말고 메인 컬러만 써줘" |
| 이미지로 만들어져서 글이 안 고쳐진다 | 도형 제작 지시 누락 | "새 장표는 반드시 도형·텍스트 상자로" 추가 |

## 용어

- **마스터**: 우리 회사 제안서의 기준 디자인(PNG)
- **design.md**: 디자인 규칙을 글로 정리한 문서. 클라이언트별로 하나씩 만듭니다.
- **슬롯**: 색이 들어가는 정해진 자리(상단 바, 삼각형, 번호 원 등). 색조정안에서 클라이언트 색이 들어갈 자리는 따로 정해 둡니다.
- **brand.json**: 클라이언트 이름, 대표 색, 로고 파일명을 적은 작은 파일
- **렌더링**: PPT를 이미지로 변환해서 눈으로 확인하는 과정
